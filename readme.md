# LLM 辩论竞技场

一个本地运行的多模型辩论工具。选择模型、填写提示词，模型依次回答、讨论并互评，自动得出排名。每场过程保存为 Markdown，方便后续使用脚本统计或人工分析。

## 快速开始

需要 Node.js 20 或更高版本，以及可调用模型的 API 密钥。

在项目目录执行：

```bash
npm ci
npm start
```

打开 http://localhost:3456，点击「连接模型」，填写对应提供方的 API 密钥并测试连接。在模型列表中勾选需要使用的模型，保存配置。

项目支持以下提供方，也支持在同一场中混用：

| 提供方 | 默认 API 地址 |
| --- | --- |
| DeepSeek | `https://api.deepseek.com` |
| GLM（智谱 Coding） | `https://open.bigmodel.cn/api/coding/paas/v4` |
| OpenCode Go | `https://opencode.ai/zen/go/v1` |

模型列表不代表所有型号都能实际调用。OpenCode 提供单模型和批量可用性测试；账户权限、套餐、额度、限流及模型停用都可能影响调用。测试和实验会消耗 API 额度。

## 排名实验

1. 选择 2–4 个模型。
2. 填写完整提示词，可包含多行文字或代码，最多 4000 字。
3. 设置每阶段循环次数和每场回答轮数，点击「开始排名实验」。
4. 查看实时讨论、投票及最终排名。

提示词就是所有模型需要回答的同一个问题，适用于 HTML 或其他领域。界面将整段输入作为一个问题，不会按分隔线拆题。默认每阶段循环 1 次，每场回答 1 轮；高级设置中可调整温度和输出 token 预算。

### 排名如何产生

新实验使用 `same-question-v7` 同题回答协议（自由篇幅）：所有模型先独立回答完全相同的用户问题，首轮不展示其他模型的答案，不让模型互相出题。若设置多轮回答，从第二轮起，各模型参考此前完整轮次的答案，围绕原问题补充、澄清或修正；同轮新答案不展示，避免后发者获得额外信息。

回答阶段不再限制 600 字目标或最多 3 个要点，模型按问题需要自行决定长度与组织方式，可给出完整代码、必要解释、边界条件和验证方法。仍要求围绕原问题、不猜测身份、不虚构工具执行、不用冗长重复代替有效内容；篇幅长不加分。输出 Token 预算、推理模型最低预算、超时、重试、讨论轮数和加赛上限保持原规则，这不是无限输出模式。互评的 800 字目标与补投的 80 字约束、投票格式及完整性检查不变。

新旧记录通过协议版本区分：`same-question-v7` 显示「同题回答（自由篇幅）」，旧 `same-question-v6` 显示「同题回答（限定篇幅）」。历史 JSON 与 Markdown 不改写；详情和排名汇总保留版本差异，不应将两种输出条件直接合并作同一实验统计。新接口不再使用 `wordLimit`，旧客户端传入该字段会被忽略。单场调试也使用相同的按需完整作答指导，但不改变其逐次参考前序回答的流程。

回答结束后，各模型阅读本场全部匿名答案，主要按正确性、完整性、相关性和论证依据互评，引用具体回答步骤并投票选出回答最好者。允许自投，不额外调用裁判。未核实的争议不能直接视为错误，是否遵循提示及答案正确性仍需人工核查，系统不自动验证规范或运行代码。旧实验不重新计算，历史记录区分同题回答、对称问答和旧讨论方式。

系统汇总本阶段所有场次的票数，选出唯一最高票者作为第一名，移除该模型，再让剩余模型围绕同一个用户问题重新独立回答和互评，依次确定第二、第三等后续名次。每个新阶段不带入上一阶段的答案或票数，最后剩下的模型获得末位。回答顺序默认逐场轮换，也可选择固定顺序。

### 回答顺序与结果

单场调试和排名实验共用起始回答顺序，通过模型旁的上下箭头调整；每场的各轮沿用该场顺序。排名实验可选「固定顺序」或「逐场轮换」：固定时所有重复与加赛沿用起始顺序，已选出的模型退出后保持剩余模型的相对顺序；轮换时每阶段从剩余模型的起始顺序开始，逐场把首位移到末位。

运行中显示实际回答顺序；结果和历史记录将每场顺序、位置对应的得票及最高票者放在一起。每阶段另按「模型 × 回答位置」统计场数、总票数、平均票数、独占最高票次数和并列最高票次数，仅统计完整有效投票的场次，避免混合不同候选阵容。旧记录没有顺序时标为未记录，不推断顺序。

可在同一题目、模型、温度和轮数下，分别运行不同固定顺序，或增加轮换模式的循环次数。N 个模型每阶段至少循环 N 次，才能让该阶段每个模型都覆盖各个位置一次。回答顺序会同时影响匿名编号和互评答案展示顺序，加赛还会改变回答轮数，因此这些统计用于观察关联，不能单独证明先后顺序造成胜负。

若最高票并列，保留本阶段候选模型和累计票数，围绕同一问题自动加赛，每次比基础设置多回答 1 轮，最多加赛 5 次。仍然并列时停止并保留并列结果；互评重试后仍缺少有效投票或调用失败时保留记录与之前已完成结果并报告错误。

基础场次为 `循环次数 ×（模型数量 − 1）`，加赛会增加场次和调用费用。例如 4 个模型、每阶段循环 2 次，基础为 6 场。

每场 N 个模型、R 轮回答需要 `N×R` 次正文调用和 N 次互评。默认每阶段一次、每场一轮时，两模型排名基础为 1 场、4 次调用；三模型为 2 场、10 次调用；四模型为 3 场、18 次调用，不含失败重试、补投票及并列加赛。页面显示基础调用次数。

讨论互评反映给定提示词下的表现。与官网榜单的比较由用户自行选择对应分类并人工完成，项目不计算外部榜单相关系数，也不直接执行代码测试或生成、编辑图像。

## 单场调试与实验记录

「单场调试」用于检查连接和模型回答，可设置辩论轮数及匿名或实名模式。它沿用逐次参考前序回答的流程，与排名实验的流程不同。正常结束或因接口错误中断后，会保存回答、模型互评、裁判评价、实际顺序与运行参数，可直接在「实验记录」查看；失败时保留已有内容。

「实验记录」统一列出排名实验与单场调试，可按类型、状态筛选，按题目摘要、模型或记录编号搜索，并按时间排序。排名实验保留阶段票数、回答位置、原题与参数；单场详情展示模型回答、互评、裁判评价、回答位置与参数，不生成阶段排名。支持下载记录 JSON、复制编号和查看原始 Markdown。手机端选择记录后显示详情，可返回列表。切换页面不会中断正在运行的实验；刷新页面可恢复最近一次排名实验的显示。服务重启后不会自动续跑未完成实验。

已有单场 Markdown 会以「历史单场」只读加载，包括子目录中的记录；已关联排名实验的场次、带实验协议的场次、排名汇总及顺序对照复评报告不会混入。旧记录没有结构化票数、运行参数或回答位置时不作推断，未标明失败的旧记录显示「历史归档」，不据此断言运行成功。原文件不做修改，也不额外调用模型。

排名实验旁边的「模型实时聊天」显示接口返回的思考过程和正文，并标明等待响应、思考中、输出中、重试以及距上次内容的秒数。面板每秒刷新，切换场次时清空，内容只保留在服务内存中，不写入 Markdown 或实验 JSON。接口未返回思考内容时只能显示正文；等待时间较长不一定代表模型已卡住。

## 记录与统计

`debates/排名实验汇总.md` 专门列出每组已完成实验的第 1、2、3、4 名，包含北京时间、题目摘要和原始结果链接，最新结果在前。实验完成后自动更新；服务启动时会补齐历史结果。两个或三个模型的实验用 `—` 表示未参加的名次，未完成或并列停止的实验不列入完整排名。也可运行 `npm run report` 手动重建。此文件自动生成，请勿手动编辑。详细结果链接指向相邻的 `experiments/` 目录。

- `debates/`：每场提示词、参与模型、辩论正文和互评结果，保存为 Markdown。文件名为 `YYYY-MM-DD_HH-mm-ss-场次ID前8位.md`；旧记录可能没有 ID 后缀。
- `experiments/`：排名实验的状态、阶段票数、排名及 Markdown 文件引用，保存为 JSON。
- `debates/debug-场次ID.json`：新单场调试的结构化记录，不保存 API 密钥、上游请求配置或临时聊天。统一浏览接口为 `GET /api/records` 和 `GET /api/records/:id`；原 `/api/experiments` 接口仍只返回排名实验。
- 新协议的每场记录包含 `exchanges`，列出回答轮次、环节、发言者和步骤；Markdown 同时记录这些信息及评价规则。旧对称问答记录还包含对话对象。
- 新实验 JSON 保存 `orderPolicy`（`rotate` 或 `fixed`），各场保存 `speakerOrder`，发言保存 `answerPosition`，投票保存 `chosenPosition`；Markdown 明确列出每轮回答顺序。
- 匿名身份通过文件头的参与模型顺序对应：参与者 A 为第一个模型，B 为第二个模型，依此类推。

互评使用可解析的投票格式：

```text
win_res：参与者A
```

运行统计脚本：

```bash
# 统计 debates/ 下的记录
node scripts/tally.cjs

# 统计指定目录
node scripts/tally.cjs debates/glm

# 输出 CSV，可导入 Excel
node scripts/tally.cjs debates/ --csv > result.csv
```

脚本递归读取含有效 `win_res` 的 Markdown，汇总各场结果及模型得票；没有有效投票的记录会跳过。它不会自动更新现有 XLSX 文件。单场胜负统计与排名实验的阶段累计排名应分别解读。

### Excel 主文件

排名与对战统计的唯一正式工作簿固定为 `debates/统计结果.xlsx`。以后每次更新 Excel 统计，都先读取这份现有工作簿，在原有工作表中更新数据、公式和来源，并保存回同一路径；不再按日期另存多份统计结果，也不重复增加同名工作表。保留已有历史数据、人工填写内容和无关格式，按场次或实验编号避免重复计入；不同实验协议继续明确区分。

`outputs/` 是可清理的过程产物目录，不是正式统计入口。浏览器测试会按需重新生成截图和模拟导出；临时 Excel 副本、备份及核对文件确认不再需要后可删除，不能用旧副本覆盖主文件。检查更新时可以使用临时文件，但只保留上述固定主文件作为日常统计入口；清理过程产物不应删除 `debates/` 或 `experiments/` 中的原始记录。部分旧导出目录含指向共享运行库的目录联接，清理时只移除联接本身，不删除联接目标。

这个约定不代表 Excel 已接入自动刷新：当前程序自动更新的是 Markdown 排名汇总，`npm run tally` 输出终端统计或 CSV；需要更新 Excel 时，仍需执行工作簿更新流程。

## 接口兼容与调用处理

OpenCode 模型由 `src/protocols/provider-protocol.cjs` 适配到 Anthropic Messages、Chat Completions 或 Responses 接口。Google 原生接口目前尚未接入。模型停用时显示上游建议的替代型号，需要用户重新选择，不会在实验中自动替换模型。

互评使用独立输出预算：普通模型为 2048 Token，代码识别的推理模型（包括 Kimi）至少为 16384 Token，不受页面最大 Token 设置影响。互评因预算截断、空正文或无有效候选投票时，用更严格的投票提示将预算翻倍重试一次（最高 65536 Token）；截断的回答即使包含投票也不采用。排名实验中重试仍失败或互评调用出错，会保存记录并停止，不用缺票场次继续排名。增加预算可能提高耗时与 API 用量。

部分推理模型会提高输出 token 预算，避免思考阶段耗尽预算。连接错误、408、429、部分 5xx 错误，以及尚未收到正文时的数据流断线，共用最多 2 次重试，分别等待 2 秒、4 秒。仅收到独立思考内容时也可重试，临时聊天框会清空该次输出并显示重试状态；已输出部分正文后断线则保存部分内容并停止实验，不把不完整回答用于排名。响应头等待上限为 120 秒，流内无新数据上限为 300 秒；这些长时间等待超时不自动重试。

仍使用 `npm start` 启动、`npm test` 检查、`npm run report` 重建排名汇总、`npm run tally` 统计投票，也可直接运行 `node src/server.js`。数据目录保持原位，旧实验记录不需要搬迁。

项目采用同一服务托管前端和 API，不需要两个端口或构建步骤。前端通过原生 ES 模块显式导入依赖，后端由 `src/app.cjs` 创建独立运行状态并装配各模块。后端按 `routes`、`providers`、`services`、`storage` 和 `runtime` 划分职责；前端按 `core`、`features` 和页面模块组织。前端需要通过服务访问，不能直接双击 HTML 使用。

`tests/module-boundaries-test.cjs` 使用临时目录和随机端口，验证运行实例隔离、临时聊天不写入实验对象、记录存储、模型目录接口，以及不同应用的记录目录互不影响。

`tests/debug-records-test.cjs` 验证单场完成/失败存档、票数身份映射、密钥不落盘、重启读取、旧 Markdown 和重复排除。`tests/debug-records-browser-test.cjs` 沿用 Playwright 环境变量，验证记录类型筛选、单场详情、历史归档、安全转义、导出和手机布局；截图保存到 `outputs/debug-records/`。

| `GLM_API_KEY` | GLM 密钥，可作为页面传入密钥的后备值 |

OpenCode 密钥在页面连接配置中填写。服务不会自动加载 `.env` 文件，环境变量需在启动前设置。当前服务适合本地使用，公开部署前需增加访问鉴权。
