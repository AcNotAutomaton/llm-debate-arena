# LLM 辩论竞技场

一个让多个 AI 大模型**轮流发言、链式辩论**的交互平台。模型们基于对方的前序回答逐轮深入讨论,最后由裁判模型打分决出胜负。

---

## 功能特点

- **链式辩论**:模型依次发言,后一个模型基于前一个的回答继续分析,形成深度对话链条
- **多 Provider 混用**:同时支持本地 vLLM 服务、DeepSeek 云端 API、GLM(智谱)云端 API 和 OpenCode 第三方聚合端点,多种来源的模型可以同台辩论
- **匿名/实名辩论**:可在设置中切换。匿名模式下模型不知道对手身份(以「参与者A/B」标识),并被告知"对手可能是人类也可能是 AI",形成盲辩;实名模式下模型可见对方真实身份
- **流式输出**:模型思考过程和回答实时推送到页面,无需等待
- **模型可用性批量测试**:对 OpenCode 第三方端点的所有模型逐个发最小推理请求,验证哪些模型真正可用(详见下文「为什么需要批量测试」)
- **输出健壮性保障**:针对"说到一半停止""一直思考中"等异常,内置三层防护(握手超时 / 流内闲置超时 / [DONE] 缺失检测 / max_tokens 截断提示 / 前端长时间无响应兜底)
- **自动记录**:每场辩论结束后自动在 `debates/` 目录生成 Markdown 文件,文件名精确到秒
- **主题切换**:支持深色/浅色主题,右上角 🌙/☀️ 一键切换

## 为什么需要批量测试模型可用性

不同 provider 的模型可用性差异很大:

| Provider | 模型可用性 | 原因 |
|----------|------------|------|
| DeepSeek(官方) | ✅ 列出的模型**全部可用** | 官方端点 `/models` 返回的模型即账号有权限调用的模型,一一对应 |
| GLM(智谱官方) | ✅ 列出的模型**全部可用** | 同上,官方端点不会列出账号无权限的模型 |
| **OpenCode(第三方聚合)** | ⚠️ 列出的模型**不一定都能用** | 第三方聚合端点把上游多家厂商的模型统一列出,但实际可用性受上游开通状态、资源包、限流、模型下线等因素影响——`/models` 能列出来 ≠ 你的 key 能调用成功 |

**实测发现**:OpenCode 端点 `/models` 返回 25 个模型,但用真实 key 逐个发推理请求时,部分模型可能返回鉴权错误、无资源包、模型不支持等错误。如果直接拿这些"列表里看起来有"的模型开启辩论,中途某个模型调用失败会中断整场辩论。

因此设置了「🧪 批量测试所有模型可用性」按钮:用填好的 API 密钥对每个模型发一次最小推理请求(`max_tokens:5`),把真实可用状态列成表显示,再决定勾选哪些模型。这一步对 DeepSeek/GLM 官方端点是"走过场"(必然全可用),但对 OpenCode 这类第三方聚合端点是**必要的前置检查**。

## 快速开始

### 安装依赖

```bash
cd llm-arena
npm install
```

### 启动服务

```bash
node server.js
```

默认地址:http://localhost:3456

### 配置模型

打开页面后,点击右上角 ⚙️ 打开设置面板:

1. **DeepSeek 模型**(推荐):
   - 在「DeepSeek API 密钥」输入框粘贴你的 API Key
   - 点击「测试 DeepSeek 连接」
   - 在模型列表中勾选你要用的模型(如 `deepseek-v4-pro`、`deepseek-v4-flash`)

2. **GLM(智谱)模型**(推荐):
   - 在「GLM API 密钥」输入框粘贴你的 API Key
   - 点击「测试 GLM 连接」
   - 在模型列表中勾选你要用的模型
   - **注意**:GLM 使用 coding 端点 `https://open.bigmodel.cn/api/coding/paas/v4`(随编程工具套餐有额度),而非普通 `paas/v4` 端点

3. **OpenCode 第三方模型**(可选):
   - 在「OpenCode API 密钥」输入框粘贴你的 API Key
   - 先点「测试 OpenCode 连接」拉取模型列表
   - **再点「🧪 批量测试所有模型可用性」**:逐个验证哪些模型真正可调用,不可用的会标红显示错误
   - 只勾选标绿(可用)的模型

4. **本地 vLLM 模型**(可选):
   - 在「vLLM 服务地址」输入你的 vLLM 地址(默认 http://localhost:8000/v1)
   - 点击「测试连接」
   - 勾选本地模型

### 开始辩论

1. 在输入框中输入你想要讨论的问题
2. (可选)在设置里切换「匿名辩论」开关
3. 点击「开始辩论」
4. 实时观看每个模型依次发言
5. 辩论结束后查看裁判评分与模型互评

辩论记录会自动保存到 `debates/` 文件夹,文件名格式为 `YYYY-MM-DD_HH-mm-ss.md`。

## 匿名辩论模式

设置弹窗中的「匿名辩论」开关控制模型之间是否知道对方身份:

| 环节 | 匿名模式(默认 ✅) | 实名模式 |
|------|------|------|
| 辩论系统提示词 | "参与者A",注入身份不确定性 | "你是 glm-4.6" |
| 历史记录标签 | `参与者B:` | `glm-4.6:` |
| 互评 transcript | 用中立标识 | 用真实模型名 |
| **裁判/存档/前端展示** | 仍显示真实名(上帝视角) | 显示真实名 |

匿名模式下,模型被告知"对手可能是人类专家,也可能是另一个 AI 模型",无法确定对方真实身份,从而使辩论更接近盲辩/图灵测试场景。

## 输出异常防护

针对真实使用中遇到的几类"输出异常",系统内置了多层防护:

| 异常现象 | 检测机制 | 表现 |
|----------|----------|------|
| 一直思考中(fetch 握手卡死) | 后端 `fetchWithHandshakeTimeout`:60s 内未收到响应头则中止 | 标红 + 报错,辩论继续下一步 |
| 说到一半停止(流内无新数据) | `readStream` watchIdle:120s 无新 token 则取消读取 | 红色提示 + 保留已收文字 |
| 流提前结束未收到 [DONE] | `readStream` 检测 `doneSeen` | 红色提示 + 保留已收文字 |
| 推理模型 content 为空 | 收集 `reasoning_content`,content 为空时回退使用 | 不再出现空白卡片 |
| max_tokens 截断 | 读取 `finish_reason === "length"` | 黄色 ℹ️ 提示 |
| SSE 断线/事件丢失 | 前端 70s 兜底计时器 | 红色「长时间无响应」提示 |

## 技术架构

- **后端**:Node.js + Express,使用 SSE(Server-Sent Events)实时推送
- **前端**:原生 JavaScript + CSS Variables 主题系统
- **API**:支持 OpenAI 兼容格式(vLLM / OpenCode)、DeepSeek API 和 GLM(智谱)coding API
- **记录**:Node.js fs 模块写入 Markdown 文件

## 项目结构

```
llm-arena/
  server.js          # 后端服务
  package.json       # 依赖配置
  node_modules/      # 依赖包
  debates/           # 辩论记录(自动生成)
  public/
    index.html       # 主页面
    app.js           # 前端逻辑
    style.css        # 样式(支持深色/浅色主题)
```

## 环境变量

- `GLM_API_KEY`:GLM(智谱)API 密钥(可选,也可以在页面设置中填写)
- `DEEPSEEK_API_KEY`:DeepSeek API 密钥(可选,也可以在页面设置中填写)
- `PORT`:服务端口(默认 3456)
